# טכנולוגיות והחלטות מרכזיות
ממשק פשוט ללא תהליך בנייה
בחרתי ב־HTML, CSS ו־JavaScript ללא Framework, כדי לצמצם תלויות ולהתמקד במוצר עובד במסגרת הזמן.
האתר מפורסם כקבצים סטטיים ב־Sites ומתקשר עם Supabase באמצעות API.
הלוגיקה הקריטית של יצירת הזמנה נמצאת בפונקציית PostgreSQL במסד הנתונים. כך ניתן לאמת את הנתונים ולשמור הזמנה באופן מבוקר, ללא שרת אפליקציה נפרד.

# מבנה הנתונים

products	ֿֿ|       קטלוג המוצרים, המחירים וסימון מוצרים פעילים

הפרדתי בין הזמנה לבין הפריטים שלה כדי לאפשר כמה מוצרים באותה הזמנה, בלי לשכפל את פרטי הלקוח בכל שורה.
בכל הזמנה נשמרים גם שם המוצר ומחירו בזמן ההזמנה. כך שינוי עתידי בקטלוג אינו משנה את פרטי ההזמנות שכבר נוצרו.

# חישוב המחיר במסד הנתונים
הדפדפן שולח מזהי מוצרים וכמויות, ולא מחיר שעליו המסד מסתמך.
הפונקציה place_cart_order בודקת שהמוצרים פעילים, קוראת את מחיריהם מהמסד ומחשבת את הסכום הסופי.
בחרתי בכך משום שניתן לשנות נתונים ובקשות בדפדפן, ולכן בדיקות בממשק בלבד אינן מספיקות. המחירים נשמרים כמספרים שלמים באגורות, כדי להימנע משגיאות עיגול בחישובים.

# שמירה מלאה ומניעת כפילויות
ההזמנה וכל הפריטים שלה נשמרים בטרנזקציה אחת. אם אחת הפעולות נכשלת, לא נשארת במסד הזמנה חלקית.
לכל בקשת הזמנה נוצר request_id ייחודי. ניסיון חוזר עם אותו מזהה ואותו תוכן מחזיר את ההזמנה הקיימת, במקום ליצור הזמנה נוספת.
שימוש באותו מזהה עם תוכן שונה נדחה. 
נעילה במסד מגינה גם מפני ניסיונות מקבילים עם אותו מזהה.
מזהה הבקשה נשמר בזיכרון הדף בלבד, ולכן ההגנה על ניסיון חוזר אינה ממשיכה לאחר רענון הדפדפן.

# הרשאות ואבטחת מידע
הגישה לנתונים מוגבלת באמצעות הרשאות ו־RLS במסד הנתונים:
- מבקרות יכולות לקרוא מוצרים פעילים ולשלוח הזמנה דרך הפונקציה המיועדת לכך.
- אין גישה ציבורית ישירה לטבלאות ההזמנות.
- כניסה לניהול מתבצעת באמצעות Supabase Auth, ובנוסף נבדק שהמשתמשת מופיעה ב־shop_admins.
- מנהלת יכולה לקרוא הזמנות ולעדכן את הסטטוס בלבד, ללא הרשאה לשנות מחירים או פרטי לקוחה.
ב־config.js נמצא מפתח ציבורי בלבד. ההגנה על הנתונים מבוססת על ההרשאות במסד, ולא על הסתרת המפתח.
הסל נשמר ב־localStorage עם מזהי מוצרים וכמויות, ללא פרטי לקוחה. אסימוני ההתחברות לניהול נשמרים בזיכרון בלבד, ולכן רענון מסך הניהול דורש כניסה מחדש.

# הרצה מקומית
1. יוצרים פרויקט Supabase ומפעילים את ה־Data API.
2. במסד חדש מריצים את קובצי ה־SQL לפי הסדר:
   - setup.sql
   - cart-upgrade.sql
   - admin-upgrade.sql
3. מגדירים ב־config.js את supabaseUrl ואת publishableKey.
4. מתיקיית הפרויקט מריצים:
python3 -m http.server 8000
5. פותחים בדפדפן את http://localhost:8000.
קובצי ה־SQL מיועדים להקמה ולשדרוג בין גרסאות; אין להריץ מחדש את כולם על מסד שכבר הוגדר.
להקמת מנהלת, יוצרים משתמשת מאומתת ב־Supabase Authentication ומוסיפים אותה ל־shop_admins באמצעות פקודת הדוגמה שבסוף admin-upgrade.sql. לאחר מכן אפשר להתחבר דרך admin.html.
אפשר לצפות בהזמנות גם דרך Supabase Table Editor, בטבלאות cart_orders ו־order_items.
