# סטודיו שולחן

חנות מינימלית למוצרי נייר וכלי כתיבה. פרויקט לתרגיל טכני מוגבל בזמן.

## סטטוס נוכחי

החנות מחוברת ל-Supabase. נבדקו מול המסד האמיתי: טעינת שישה מוצרים, יצירת הזמנה, ניסיון חוזר ללא כפילות, דחיית כמות לא תקינה וחסימת קריאת הזמנות ציבורית. האתר פורסם ב-Sites. בדיקת ממשק אוטומטית בדפדפן טרם הושלמה.

## הפעלה

1. צרו פרויקט Supabase.
2. ב-SQL Editor הריצו פעם אחת את `setup.sql`.
3. ב-`config.js` הגדירו Project URL ומפתח Publishable או anon ציבורי. אין להשתמש ב-service_role, Secret key או בסיסמת מסד הנתונים.
4. הגישו את תיקיית הפרויקט בשרת סטטי, לדוגמה `python3 -m http.server 8000 --directory .`.
5. פתחו `http://localhost:8000`.

## התנהגות המערכת

- קטלוג נטען ישירות מ-Supabase REST API. אין קטלוג מקומי שמתחזה לנתונים אמיתיים.
- חיפוש וסינון לפי קטגוריה — התוספת מעבר לדרישות הבסיס.
- הזמנה של מוצר אחד בכמות 1–20, עם שם ואימייל ליצירת קשר.
- שמירה ב-Postgres באמצעות פונקציה מאמתת. המחיר ושם המוצר נקראים מהמסד, ולא מתקבלים מהלקוח.
- מזהה בקשה ייחודי מונע יצירת שתי הזמנות מאותה בקשה בעת ניסיון חוזר לאחר תקלה ברשת, כל עוד הטופס נשאר פתוח ללא שינוי.
- צפייה בהזמנות: Supabase Dashboard → Table Editor → orders. בחרו מיון לפי created_at מהחדש לישן. אין גישה ציבורית לפרטי ההזמנות.
- מצבי טעינה, שגיאה, ריק והצלחה; התאמה לנייד וממשק עברי.

## החלטות מרכזיות

- HTML, CSS ו-JavaScript ללא תהליך בנייה: מעט תלות בכלים וזמן הקמה קצר. Supabase מספק את שכבת הנתונים ו-API.
- PostgreSQL RLS והרשאות מפורשות: הציבור יכול לקרוא מוצרים פעילים בלבד. טבלת ההזמנות חסומה לציבור, ויצירה אפשרית רק דרך פונקציה שמאמתת את הקלט.
- SECURITY DEFINER נדרש לכתיבה מוגבלת בטבלה חסומה; search_path ריק ושמות טבלאות מלאים מצמצמים סיכוני החלפת אובייקטים.
- המחיר נשמר באגורות כמספר שלם; שם ומחיר המוצר נשמרים גם בהזמנה כדי ששינוי קטלוג לא ישנה היסטוריה.
- מסך Supabase משמש לצפייה בהזמנות במסגרת הזמן, במקום מערכת ניהול נפרדת.

## מגבלות ומה הייתי עושה בעוד שעה

אין סל רב-מוצרים, סליקה, משלוחים או שליחת אימיילים. הטופס אוסף אימייל ליצירת קשר בלבד. אין כרגע הגבלת קצב להגנת API מהזמנות ספאם; לפני שימוש מסחרי אוסיף rate limiting ואמצעי מניעת בוטים. הייתי מוסיפה התחברות מנהל ומסך ניהול ייעודי, סטטוסים להזמנות ובדיקות אינטגרציה אוטומטיות מול מסד בדיקה.

## בדיקות לפני הגשה

- מוצרים שמופיעים באתר תואמים ל-products; שינוי שם במסד נראה לאחר רענון.
- הזמנה תקינה מופיעה ב-orders עם הכמות והמחיר הנכונים.
- ניסיון חוזר עם אותו request_id אינו יוצר שורה נוספת.
- בקשה ישירה עם כמות לא תקינה נדחית.
- SELECT ציבורי ל-orders אינו מחזיר פרטי לקוחות.
- חיפוש ללא תוצאות, תקלה ברשת ושימוש בנייד מוצגים בצורה תקינה.
