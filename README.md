# סטודיו שולחן

חנות עברית למוצרי נייר וכלי כתיבה עם סל קניות שמתעדכן מיד, סיכום הזמנה ושמירה ב-Supabase.

- אתר: https://studio-desk-shop.workspace-616380.chatgpt.site
- GitHub: https://github.com/adiamar216-colman/studio-shop

## מה עובד

מוצרים נטענים מ-Supabase; חיפוש וסינון לפי קטגוריה; הוספת כמה מוצרים לסל; שינוי כמות והסרת פריטים; מונה פריטים וסכום שמתעדכנים מיד; סיכום הזמנה לפני השליחה ואישור עם מספר הזמנה. נוסף לוגו SVG מקורי וממשק עברי רספונסיבי.

**התוספת למטלה:** סל קניות רב-מוצרים. לקוח שרוצה כמה מוצרים מוסר את פרטיו פעם אחת ומקבל הזמנה אחת. חיפוש וסינון הם תוספת נוספת.

## הפעלה

1. צרו פרויקט Supabase והפעילו את Data API.
2. בהרצה ראשונה בלבד הריצו את `setup.sql` ב-SQL Editor.
3. הריצו את `cart-upgrade.sql`. בפרויקט הקיים מספיק להריץ רק את העדכון, לא שוב את setup.sql.
4. הגדירו ב-`config.js` את Project URL ואת המפתח הציבורי Publishable או anon. אין להכניס Secret key או service_role.
5. הפעילו `python3 -m http.server 8000 --directory .` ופתחו http://localhost:8000.

## צפייה בהזמנות

ב-Supabase Table Editor:

- `cart_orders`: שורה אחת לכל הזמנה, פרטי הלקוח, הסכום והתאריך.
- `order_items`: המוצרים בהזמנה, מקושרים דרך `order_id` ל-`cart_orders.id`.

## החלטות מרכזיות

- HTML, CSS ו-JavaScript ללא תהליך בנייה, כדי לצמצם תלויות ולהגיע למוצר עובד בזמן.
- `products` הוא מקור האמת לקטלוג ולמחירים. הדפדפן שולח מזהי מוצרים וכמויות בלבד; מחיר ושם מוצר נשמרים כצילום מצב בהזמנה.
- המחירים נשמרים כמספרים שלמים באגורות, ללא שגיאות עיגול בחישוב.
- הזמנה נשמרת בפונקציית PostgreSQL אחת ובטרנזקציה אחת: כל הפריטים נשמרים יחד, או שלא נשמר דבר.
- מזהה בקשה ייחודי ונעילה לפי מזהה הבקשה מונעים כפילות בניסיון חוזר מאותו טופס. בקשה עם אותו מזהה ותוכן שונה נדחית.
- RLS והרשאות מפורשות: קריאה ציבורית של מוצרים פעילים בלבד. אין גישה ציבורית לטבלאות ההזמנות. פונקציית SECURITY DEFINER עם search_path ריק מאמתת את הקלט לפני הכתיבה.
- מסך Supabase משמש לניהול במסגרת הזמן. הסל הוא מצב זמני בדף; רענון מנקה סל שטרם נשלח.

## בדיקות

בדיקות הגרסה הראשונה מול מסד אמיתי עברו: טעינת קטלוג, יצירת הזמנה, ניסיון חוזר ללא כפילות, דחיית כמות לא תקינה וחסימת קריאת הזמנות ציבורית.

בגרסת הסל עברו: הוספת מוצרים שונים, עדכון מונה, שינוי כמות, סיכום ושליחת הזמנה דרך הממשק (שלוש יחידות משני מוצרים, 90 ש״ח). מול ה-API נבדקו ניסיונות חוזרים מקבילים ללא כפילות, סל ריק, מוצר כפול, כמות שגויה, שינוי נתונים באותו מזהה בקשה וחסימת קריאת שתי טבלאות ההזמנות לציבור.
